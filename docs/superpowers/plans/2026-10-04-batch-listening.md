# Schwanki Batch Listening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn a triaged lesson batch into a ~90-second two-voice listening pack (ElevenLabs TTS dialogue) that uses exactly the batch's words + already-known words, credit-gated at 2 credits, free on BYOK.

**Architecture:** New `batches` entity (created at triage approval) + `listening_packs` / `listening_pack_words` tables. New `packages/listening` (prompt builder, word-coverage verifier, ElevenLabs dialogue renderer, pricing). One thin edge function `generate-listening` mirroring `generate-mnemonic`'s JWT guard + BYOK-first key resolution. New `/listen` tab in the PWA. Spec: `docs/superpowers/specs/2026-10-04-batch-listening-design.md`.

**Tech Stack:** same as mnemonic plan — pnpm monorepo (`npx pnpm@9.15.0`), React 19 + vite 8 + vitest 5 (apps/web), vitest 2 + TS 5.6 (packages), Deno edge functions on local Supabase.

## Global Constraints

- Use `npx pnpm@9.15.0` for ALL pnpm commands.
- If Docker stalls: `DOCKER_CONFIG=/tmp/docker-config-schwanki`. Start stack: `DOCKER_CONFIG=/tmp/docker-config-schwanki supabase start`.
- `supabase status -o env` values are QUOTED — strip quotes: `grep '^KEY=' | cut -d= -f2 | tr -d '"'`.
- Edge runtime env file is `supabase/functions/.env` (gitignored). After changing it, `supabase stop && supabase start`.
- Edge functions import `@schwanki/*` mapped to `supabase/functions/_vendor/`, generated by `scripts/vendor-edge.sh`. After ANY change under `packages/`, re-run `bash scripts/vendor-edge.sh`.
- Never commit `.env` files. Verify with `git status` before every commit.
- Never leave dev/preview servers running after verification.
- Palette (tailwind tokens): `cream: "#FAF6EF"`, `ink: "#1A1712"`, `beak: "#E8562A"`.
- Copy strings in this plan are spec — use them verbatim.
- A user's failing BYOK key must NEVER silently fall back to our keys (which would bill credits). Surface the failure.
- ElevenLabs direct adapter ALREADY EXISTS: `packages/mnemonic/src/adapters.ts` (`provider === "elevenlabs"`, POST `https://api.elevenlabs.io/v1/text-to-speech/{voiceId}?output_format=mp3_44100_128`). Reuse it — do NOT write a second ElevenLabs client.
- **Synchronous v1 (deliberate spec deviation):** generation runs inside the edge-function request, not via `llm_jobs`. Script gen (~10 s) + one dialogue TTS call stays well under edge time limits. If timeouts appear on 40-word packs, move to `llm_jobs` type `enrich_listening` as a follow-up.
- **No push notification in v1 (deliberate spec deviation):** the user is waiting on the generating screen; pushes only matter for async. Defer.
- Rate limit: 10 packs/hour/user, measured as `count(listening_packs where user_id, created_at > now() - 1 hour) >= 10`.
- Credit: 2 credits flat per pack. Free path requires user keys covering BOTH the text provider AND elevenlabs. Debit ONLY on persisted success. Partial-script (missing words after retry) still debits — the audio is real (spec §7).

### Task 1: Migration 0010 — batches & listening schema

**Files:**
- Create: `supabase/migrations/0010_batch_listening.sql`

**Interfaces:**
- Produces: tables `batches`, `listening_packs`, `listening_pack_words`; column `cards.batch_id`. Consumed by Tasks 2, 5, 6, 7.

- [ ] **Step 1: Write the migration**

```sql
-- Batch listening: lesson batches + listening packs (spec 2026-10-04 §2, §4.4)

create table batches (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references auth.users(id) on delete cascade,
  source_id uuid references sources(id) on delete set null,
  label text not null,               -- e.g. '2026-09-30' (triage day grouping)
  language text not null,
  created_at timestamptz not null default now(),
  unique (user_id, source_id, label) -- get-or-create at triage approval
);
alter table batches enable row level security;
create policy "own batches" on batches for all
  using (auth.uid() = user_id) with check (auth.uid() = user_id);

alter table cards add column batch_id uuid references batches(id) on delete set null;
create index cards_batch_idx on cards(batch_id);

create table listening_packs (
  id uuid primary key default gen_random_uuid(),
  batch_id uuid not null references batches(id) on delete cascade,
  user_id uuid not null references auth.users(id) on delete cascade,
  part int not null default 1,       -- overflow batches: part 2, 3, ...
  script jsonb,                      -- { lines: [{speaker, text, translation}], words_used: uuid[] }
  audio_path text,
  voices jsonb,                      -- { a: voiceId, b: voiceId }
  model_used text,
  cost_cents int not null default 0,
  missing_words text[] not null default '{}',  -- fronts that didn't make the cut
  status text not null default 'queued' check (status in ('queued','ready','failed')),
  created_at timestamptz not null default now()
);
alter table listening_packs enable row level security;
create policy "read own packs" on listening_packs for select using (auth.uid() = user_id);
-- writes are service-role only (edge function), except status retry resets:
create policy "retry own failed pack" on listening_packs for update
  using (auth.uid() = user_id) with check (auth.uid() = user_id and status in ('queued','failed'));

create table listening_pack_words (
  pack_id uuid not null references listening_packs(id) on delete cascade,
  card_id uuid not null references cards(id) on delete cascade,
  made_it bool not null,
  primary key (pack_id, card_id)
);
alter table listening_pack_words enable row level security;
create policy "read own pack words" on listening_pack_words for select
  using (exists (select 1 from listening_packs p where p.id = pack_id and p.user_id = auth.uid()));
-- inserts are service-role only
```

Reuse the existing `card-media` bucket for audio — its policies are owner-scoped on `foldername(name))[1]` = user_id. Pack audio path: `{user_id}/listening/{pack_id}.mp3`.

- [ ] **Step 1: Pricing**

```ts
export const LISTENING_PACK_COST = 2;
/** Max target words per pack; overflow becomes part 2+ (spec §4.1). */
export const PACK_TARGET_CAP = 40;
/** FSRS familiarity bar for the known-word pool (spec §4.1). */
export const KNOWN_STABILITY_DAYS = 21;
export const KNOWN_MIN_REPS = 3;
export const KNOWN_POOL_SIZE = 40;
```

- [ ] **Step 2: Prompt builder**

`buildScriptPrompt({ targets: {front, back, reading}[], knownPool: string[], language })` → `{ system, user }` strings. Requirements baked into the prompt:

- Strict JSON output: `{ "lines": [{"speaker": "a"|"b", "text", "translation"}], "words_used": [...] }` — same structured-output discipline as parser Tier 2.
- EVERY target word's front must appear verbatim in some `text`.
- Otherwise only known-pool words + function words; casual dialogue register; ~1 short exchange per 2 targets; target-language lines, English translations.
- Schwanki tone lives in the wrapper copy, NOT the script — scripts stay natural (spec §3 note: comprehensible beats spicy in audio content).

- [ ] **Step 3: Coverage verifier**

`verifyCoverage(script: PackScript, targets: {id, front}[]): { missing: {id, front}[] }`.
Match rule: CJK fronts (any char in `\u4e00-\u9fff\u0e00-\u0e7f`) → substring match against concatenated `text`; Latin fronts → case-insensitive word-boundary regex, plus the trim/lower normalization from the dedup key. Pure function, table-driven tests including zh, th, en cases and a fused-pinyin case (`恶心` front, script contains `恶心`).

### Task 5: Edge function `generate-listening`

**Files:**
- Create: `supabase/functions/generate-listening/index.ts`
- Create: `supabase/functions/generate-listening/pipeline.ts`
- Modify: `supabase/functions/.env` (add `ELEVENLABS_API_KEY` for the our-keys path — never commit)

**Interfaces:**
- Consumes: Tasks 1–4. Produces: HTTP endpoint `POST /functions/v1/generate-listening { batchId }`.

- [ ] **Step 1: Thin index.ts**

Copy the `generate-mnemonic/index.ts` shape verbatim: user-JWT guard (reject service role), `runPackGeneration(user, params)` → `{ status, body }`.

- [ ] **Step 2: Pipeline**

1. Load batch (RLS-scoped via user's own select — use service client but check `user_id === user.id` explicitly, same trust posture as generate-mnemonic).
2. Rate limit: `listening_packs` count last hour ≥ 10 → 429.
3. Target selection: batch's cards not yet in any `listening_pack_words` with `made_it` or attempted — simplest: all batch cards, oldest `created_at` first, cap `PACK_TARGET_CAP` (40). `part = count(existing packs for batch) + 1`.
4. Known pool: `card_state` where `stability >= 21 OR reps >= 3`, sample 40 fronts, excluding targets.
5. **Key resolution (BYOK-first, never silent fallback):** text = sentence-capable provider per existing capability order (anthropic/openai/openrouter); audio = elevenlabs. Both user-keyed → free path. Any ours → credit path: check balance ≥ `LISTENING_PACK_COST` up front.
6. Script: structured-output call → parse JSON → `verifyCoverage`. Missing → ONE retry appending `missing: [...]` to the prompt. Still missing → proceed, record fronts in `missing_words`.
7. TTS: `renderDialogue` (Task 4). Voice map by batch language.
8. Persist: upload `{user_id}/listening/{pack_id}.mp3` to `card-media` bucket; insert pack (`status 'ready'`, script, voices, model_used, cost_cents) + `listening_pack_words` rows (`made_it` per verifier). Debit `LISTENING_PACK_COST` with reason `enrich_listening` + pack id ONLY after persistence succeeds.
9. Failures: TTS/storage failure → pack row `status 'failed'`, NO debit, error in response body. Response: `{ packId, status, missingWords }`.
